# Bitácora de tropiezos

Cada vez que algo no salió como dice este skill, se anota. Sirve para dos
cosas: que el agente no tropiece dos veces con lo mismo en este negocio, y que
Finangher pueda corregir el sistema o el skill.

Archivo: `~/.finangher/bitacora.md`. Vive en la computadora del dueño. **Nada
sale de ahí sin su permiso.**

## Qué se anota

| Tipo | Ejemplo |
|---|---|
| **Pantalla distinta** | Un botón con otro nombre, un paso que ya no existe |
| **Trampa** | Dos productos casi iguales; el carrito traía datos de otra venta |
| **Error del sistema** | Un mensaje con un carácter roto; «Enviado» sin haberse enviado |
| **Equivocación del agente** | Eligió mal, asumió un dato, tuvo que corregir |
| **Corrección del dueño** | El dueño dijo «no» o cambió algo en la confirmación, y por qué |
| **No se pudo** | El skill no cubría lo que se pidió |

## Formato

```markdown
## <fecha> · <tipo>
- Qué se intentaba: <una línea>
- Qué pasó: <una línea>
- Dónde: <pantalla o paso>
- Cómo se resolvió: <una línea, o «no se resolvió»>
```

**Sin datos de clientes ni de ventas.** No van nombres, DNI, RUC, teléfonos,
montos ni números de comprobante. Se describe la situación («dos contactos con
el mismo DNI»), no a la persona.

## Cuándo se usa

- **Al empezar una venta:** leer la bitácora. Lo que ya pasó en este negocio es
  lo primero que hay que cuidar.
- **Al terminar:** si hubo un tropiezo, anotarlo antes de cerrar.

## Compartirla con Finangher

Solo si el dueño quiere. Cuando haya anotaciones nuevas, y sin interrumpir una
venta, ofrecerlo una vez:

> Anoté <N> cosas que no funcionaron como debían. ¿Se las envío a Finangher
> para que las corrijan? No incluyen datos de tus clientes ni de tus ventas.

- **Sí** → mostrarle el texto exacto que se va a enviar y enviarlo por el canal
  **Soporte** de Finangher (el enlace «Soporte» del menú). Marcar esas
  anotaciones como enviadas.
- **No** → no volver a preguntar por esas mismas anotaciones.

Nunca enviar la bitácora de forma automática, ni a ningún otro destino.
